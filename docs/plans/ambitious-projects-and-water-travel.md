# Ambitious projects and water travel

The user's mansion turns failed before a recorded build. Existing block-by-block JSON is too cumbersome for large coherent structures; failures currently hide their category and drop completed-history context. The user requests durable plans, execution in sensible stages, and player-like boat travel for Claude's invited body.

1. Compact builds: keep individual block operations. Add operations with shape=box, inclusive x/y/z through x2/y2/z2, mode=solid|shell|omit. Solid fills a cuboid; shell emits its boundary; omit removes only already planned cells, never world blocks. Later shapes/point details can override previously generated plan cells, but duplicate explicit point coordinates still fail. Keep dimensions32/side, boundingvolume8192, max128 shapes and max65536 expanded visits. All final materials and bounds fail closed. Existing world preflight remains unchanged. Independent tests verify geometry, hollow interiors, doors/windows, limits and no hazard bypass. Script/initiative limits count expanded placements.
2. Project ledger and execution: add a private bounded ProjectStore and project tool. Saved owner-authorized projects contain title/goal/layout and ordered steps {id,description,tool,args}; tools limited to observe_world, survey_area, check_build, build, build_in_character, experience and memory read/list/write. Persist running before execution and actual success/error receipts after execution. Pending steps execute in order; interrupted running steps require inspection and never automatically replay. Up to8 projects,32 steps/project, bounded JSON and total planned32768 build placements. Existing stages remain immutable once work begins. Owner-only save/start/pause/resume; list/read available to permitted players. Runtime may execute the next saved step without another API call while its real authorized owner remains online, permissions current, plugin unpaused and worker idle. Human jobs take priority; stale project effects fail closed. Snapshot includes bounded project summaries so Claude doesn't forget the goal, footprint, milestones or actual progress.
3. Error diagnostics: identify truncated provider output and timeouts using safe codes, never log API payloads or keys; preserve interrupted requests/progress. Give actionable messages without blindly repeating completed world work.
4. Boat travel: only one owned tagged ordinary oak boat, never a player's/chest boat. The existing invited body can board its own boat, use bounded loaded-water navigation/velocity to follow friends across surface water, and safely step ashore. Never move unrelated passengers, force-load chunks, duplicate unloaded bodies/boats, or touch player inventories. Pause/stay/dismiss stop propulsion; body observation reports vehicle state. Pure navigation tests and a real server check are required.
5. Integrate and verify: update schemas/persona to plan first, execute authorized work without repeated confirmation, use compact primitives and report actual stages. Keep all current protection, API caching and hot-runtime-loader safeguards. Run builds and mock/pure tests only here; no billable API test or historical repair script. Apply through the compatible runtime updater if the initial loader is installed.
